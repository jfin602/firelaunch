# AWS media boundary (operator review required)

`template.yaml` is a declarative proposal for two private SSE-S3 buckets, a GET/HEAD-only CloudFront distribution with signed S3 origin access, and separate uploader, worker and publisher roles. It is **not deployed** by P6/P2. Apply only after operator review of account, region, budget, IAM trust principals, DNS, media rights, logging, retention and rollback. Never paste credentials into template parameters or Git.

Pass the exact HTTPS Studio origin and existing **same-account role names** to the template. Those roles also need their own reviewed `sts:AssumeRole` permission for the generated roles they use; the template grants no cross-account trust. The central services' prefix-wide permissions are narrowed at the authenticated owner/asset repository boundary before any storage call.

- Originals live only at `media/<opaque owner>/<opaque project>/<opaque asset>/original/<opaque upload>.mp4`. The control plane assumes `UploaderRole` for create/part/complete/abort. The isolated `WorkerRole` performs trusted HEAD/read verification; the web host does not stream large originals. A future direct browser multipart signer issues short-lived, scoped PUTs after authenticated ownership and CSRF checks. The S3 CORS rule permits only the configured HTTPS Studio origin; CORS is not authorization. Incomplete multipart uploads expire after one day. Completed originals require explicit retention/deletion operations; bucket versioning consumes storage until versions are cleaned under an approved retention policy.
- Worker output is staged at `media/<scope>/staged/<rendition>/...` and conditionally written to `media/<scope>/delivery/<rendition>/<content version>/...` only after verification. The bucket policy allows CloudFront to read **only** delivery objects, with the exact distribution ARN as `AWS:SourceArn`; staged and original objects are not CDN-visible. The worker role can write staging only; the separately assumed publisher role reads staging and writes delivery after the P5 READY, owner and rights gates. The storage class exposes both operations, but IAM credentials select the permitted subset. These IAM roles intentionally have no bucket listing, public ACL, IAM administration or cross-account trust.
- Configure `FIRELAUNCH_MEDIA_AWS_REGION`, `FIRELAUNCH_MEDIA_ORIGINALS_BUCKET`, `FIRELAUNCH_MEDIA_DELIVERY_BUCKET`, `FIRELAUNCH_MEDIA_CLOUDFRONT_ORIGIN` (exact `https://<distribution-or-dedicated-host>/`) and `FIRELAUNCH_MEDIA_CLOUDFRONT_HOSTS` (comma-separated exact host allowlist) in **server/worker environment only**. Use short-lived assumed-role credentials from the AWS provider chain. Keep CloudFront host, buckets and staging origin consistent with the reviewed stack output. S3 client injection in tests is offline; this template is not evidence that any AWS resources exist.
- Set HLS `.m3u8` to `application/vnd.apple.mpegurl`, `.ts` to `video/mp2t`, and `.m4s`/`.mp4` to `video/mp4`. The adapter sets these types and `Cache-Control: public, max-age=60` on rendition objects; CloudFront policy caps TTL at 300 seconds and error caching at zero. OAC protects S3, **not public viewer access** to approved CloudFront URLs. Revocation of future releases is immediate at the control plane; cached/offline bytes may remain until TTL or an independently reviewed invalidation completes.
- AWS multipart ETags are not full-object checksums. The adapter requires S3 HEAD size/type/encryption/full-object CRC64NVME and streams a full SHA-256 comparison on a capacity-controlled worker path before a DB upload is marked verified. P3 must not run that large read on the small web API host. P3 supplies presigned-part URL issuance, durable upload state, size quotas and abandoned-session cleanup. P4 supplies the FFmpeg worker and complete HLS graph validation. P5 owns creator-approved rights checked publication. Nothing in this template alone authorizes publication or qualifies Vega playback.

Before applying, validate the CloudFormation template with the target AWS account and inspect the change set. Confirm direct S3 anonymous reads of both buckets and staged CDN paths fail, while a reviewed delivery object has the expected HTTPS response and MIME. Record actual cost/usage and source rights separately at P8. Do not use a website origin, public bucket, account root key or a shared viewer entitlement claim.
