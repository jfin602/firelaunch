## Foundation adaptation checkpoint (c6 P2)

Upstream reference: [AWS Video on Demand on AWS Foundation](https://github.com/aws-solutions-library-samples/video-on-demand-on-aws-foundation/tree/a432b219910309dd1a7cec661004b980162a98e0), pinned commit `a432b219910309dd1a7cec661004b980162a98e0` (inspected 2026-10-14). This is a **selective sidecar adaptation**, not a deployment of upstream CDK or a claim that the upstream template was forked and tested. The inspected `source/cdk/lib/vod-foundation-stack.ts` creates new source/destination buckets and a CloudFront distribution, permits client-uploaded job settings, and writes a public-facing jobs manifest on completion. Those defaults conflict with FireLaunch approval. No upstream stack, custom resource, job-submit Lambda or job-complete Lambda may be deployed unchanged.

`foundation-overlay.yaml` references **existing bucket names** and creates only a paused one-job on-demand MediaConvert queue, narrow MediaConvert/submit/observe roles, two package-backed Lambdas, an account/Region/queue-scoped EventBridge rule (disabled by default) and an encrypted 14-day dead-letter queue. It creates **no S3 bucket, CloudFront distribution, bucket policy, object copy, deletion, or lifecycle rule**. Its Lambda artifact parameters are required immutable S3 package coordinates; P3 must implement, package and review `submit.handler` and `observe.handler` before any change set. In particular, this P2 template is not currently deployable with a working Lambda package. Activation requires P3 code and a separate operator-approved change set. The MediaConvert role can read only `media/*/*/*/original/*` from the originals bucket and write only `media/*/*/*/staged/*` in the delivery bucket. It cannot write `delivery/*`; the submit/observe roles cannot publish. Existing `template.yaml`'s OAC bucket policy allows CloudFront only `media/*/*/*/delivery/*`, scoped to that distribution ARN. A real operator must verify the deployed bucket policy has **no other CloudFront, public, cross-account or staging read grants** before enabling a job.

The upload trigger is a direct `SubmitFunction` invocation by the reviewed same-account `ControlPlaneRoleName` **after** the existing authenticated upload is verified and a managed attempt is durably reserved. There is deliberately no raw S3 ObjectCreated trigger: multipart completion, retries or arbitrary browser objects alone cannot pay for a job. P3's handler must re-read the owned durable intent and verified upload, check original HEAD/size/checksum, fixed queue/profile hash, source and staging keys, and current rights/quota before `CreateJob`. No caller-supplied MediaConvert settings, output destination, role or queue may pass through. The checked-in `hls-avc-aac-v1.settings.json` is the fixed H.264/AAC 480p/720p HLS starting profile; only its trusted source and private destination placeholders may be filled. Its hash and actual MediaConvert acceptance/device compatibility remain P3/live qualifications.

EventBridge filters native `aws.mediaconvert` job-state changes to this account, Region and queue. The rule is **disabled** until P3's observe handler works. Routing is not authentication: the handler must call MediaConvert `GetJob` with its AWS role in the configured account/Region, load the registered job attempt from Postgres, and compare job ID, queue, MediaConvert role, exact original and staging URIs, intent token and fixed profile hash. `apps/server/src/media-convert-event.ts` defines the fail-closed normalization after that trusted lookup. The event may only update the private attempt state; `COMPLETE` requires a separate verified HLS graph before READY and never publishes. Duplicate/out-of-order events follow the P1 repository state machine. DLQ replay and periodic `GetJob` polling reconcile missing events; an unresolved `CreateJob` response must be operator-reviewed after the one-minute token window, not blindly resubmitted. ERROR/CANCELED remain private failures. P3 must arrange authenticated DB access for handlers or a bounded internal control-plane callback; do not put DB credentials in templates or event payloads.

### Operator sequence (not executed)

1. Inventory real originals/delivery bucket names, versioning, encryption, OAC distribution ARN, existing policies, objects, in-flight FFmpeg jobs and the stack that owns each resource. Preserve all originals, staged and published versions. Do not replace/import a bucket or attach a second public CDN. Existing `template.yaml` is a historical proposal, not an upgrade target.
2. Finish P3 Lambda packages and offline security/replay checks. Pin the package by SHA-256 path and S3 object version. Produce and inspect a CloudFormation **change set only** for `foundation-overlay.yaml`, including IAM trust/permissions, regional MediaConvert support and quotas, EventBridge target/DLQ, artifact, logging permissions and any resulting replacements. The operator approves execution separately.
3. Keep the queue `PAUSED` and event rule `DISABLED` until DB/handler integration, hard admission quotas, source rights, a small owned test asset and a reviewed AWS Budget alert exist. A budget alert is visibility, not a billing cap. Enforce max input bytes/duration, at most three attempts, account/creator minute budgets and in-flight admission in FireLaunch; queue concurrency one is only a throughput bound, not a spend ceiling.
4. Prove anonymous S3 reads deny originals and staging; prove a staging URL through the existing CloudFront host denies; prove only creator-approved immutable `delivery/` bytes are available through that host. Inspect real policy simulation and HTTP responses. Offline template tests prove planned policy shape only. Then explicitly enable the rule/queue with an operator-reviewed change set and process one rights-cleared short sample.
5. On failure, pause queue and disable rule first, drain/reconcile registered jobs, preserve all object versions and DB rows, and revert the overlay by a reviewed change set. Keep previously READY legacy renditions and the old publication path until P3/P4 regressions pass. Never roll back by deleting buckets, sources or media records.

Failed, canceled and lost-event attempts can leave **orphaned private staging objects**. P3 must maintain an inventory from durable intent prefixes and periodically compare it with S3 listings under a bounded owner scope. Quarantine discrepancies for operator review; no automatic lifecycle rule in this overlay deletes source or staged bytes. A later retention policy needs a rights/forensics window and separate approval.

No AWS change set, paid MediaConvert call, policy simulation or live CDN denial was run in P2. Real account policy and profile compatibility remain pending.

# AWS media boundary (operator review required)

`template.yaml` is a declarative proposal for two private SSE-S3 buckets, a GET/HEAD-only CloudFront distribution with signed S3 origin access, and separate uploader, worker and publisher roles. It is **not deployed** by P6/P2. Apply only after operator review of account, region, budget, IAM trust principals, DNS, media rights, logging, retention and rollback. Never paste credentials into template parameters or Git.

Pass the exact HTTPS Studio origin and existing **same-account role names** to the template. Those roles also need their own reviewed `sts:AssumeRole` permission for the generated roles they use; the template grants no cross-account trust. The central services' prefix-wide permissions are narrowed at the authenticated owner/asset repository boundary before any storage call.

- Originals live only at `media/<opaque owner>/<opaque project>/<opaque asset>/original/<opaque upload>.mp4`. The control plane assumes `UploaderRole` for create/part/complete/abort, bounded HEAD verification and orphan deletion under that prefix. The isolated `WorkerRole` performs trusted full SHA-256 read verification; the web host does not stream large originals. Direct browser multipart signing issues short-lived, scoped PUTs after authenticated ownership and CSRF checks. The S3 CORS rule permits only the configured HTTPS Studio origin; CORS is not authorization. Incomplete multipart uploads expire after one day. Deleting an orphan in the versioned originals bucket creates a delete marker; noncurrent bytes still require an operator-approved retention policy.
- Worker output is staged at `media/<scope>/staged/<rendition>/...` and conditionally written to `media/<scope>/delivery/<rendition>/<content version>/...` only after verification. The bucket policy allows CloudFront to read **only** delivery objects, with the exact distribution ARN as `AWS:SourceArn`; staged and original objects are not CDN-visible. The worker role can write staging only; the separately assumed publisher role reads staging and writes delivery after the P5 READY, owner and rights gates. The storage class exposes both operations, but IAM credentials select the permitted subset. These IAM roles intentionally have no bucket listing, public ACL, IAM administration or cross-account trust.
- Configure `FIRELAUNCH_MEDIA_AWS_REGION`, `FIRELAUNCH_MEDIA_ORIGINALS_BUCKET`, `FIRELAUNCH_MEDIA_DELIVERY_BUCKET`, `FIRELAUNCH_MEDIA_CLOUDFRONT_ORIGIN` (exact `https://<distribution-or-dedicated-host>/`) and `FIRELAUNCH_MEDIA_CLOUDFRONT_HOSTS` (comma-separated exact host allowlist) in **server/worker environment only**. Use short-lived assumed-role credentials from the AWS provider chain. Keep CloudFront host, buckets and staging origin consistent with the reviewed stack output. S3 client injection in tests is offline; this template is not evidence that any AWS resources exist.
- Set HLS `.m3u8` to `application/vnd.apple.mpegurl`, `.ts` to `video/mp2t`, and `.m4s`/`.mp4` to `video/mp4`. The adapter sets these types and `Cache-Control: public, max-age=60` on rendition objects; CloudFront policy caps TTL at 300 seconds and error caching at zero. OAC protects S3, **not public viewer access** to approved CloudFront URLs. Revocation of future releases is immediate at the control plane; cached/offline bytes may remain until TTL or an independently reviewed invalidation completes.
- AWS multipart ETags are not full-object checksums. The adapter requires S3 HEAD size/type/encryption/full-object CRC64NVME and streams a full SHA-256 comparison on a capacity-controlled worker path before a DB upload is marked verified. P3 must not run that large read on the small web API host. P3 supplies presigned-part URL issuance, durable upload state, size quotas and abandoned-session cleanup. P4 supplies the FFmpeg worker and complete HLS graph validation. P5 owns creator-approved rights checked publication. Nothing in this template alone authorizes publication or qualifies Vega playback.

Before applying, validate the CloudFormation template with the target AWS account and inspect the change set. Confirm direct S3 anonymous reads of both buckets and staged CDN paths fail, while a reviewed delivery object has the expected HTTPS response and MIME. Record actual cost/usage and source rights separately at P8. Do not use a website origin, public bucket, account root key or a shared viewer entitlement claim.
