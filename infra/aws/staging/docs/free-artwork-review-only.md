# Exact free artwork viewer policy — review-only proposal

Status: local template proposal only, 2026-10-20. **LIVE PUBLIC POSTER ACCESS IS NOT QUALIFIED.** No CloudFormation change set, CloudFront update, IAM change, S3 write, creator publication or paid job was performed by this correction. Root version remains 0.6.7.

## Proposed scope

`ApprovedFreeArtworkKey` is a single optional exact S3 delivery object key. Empty (the default) denies every poster. Its parameter pattern requires `media/<32-hex creator>/<32-hex project>/<32-hex artwork asset>/delivery/artwork/rel_<32-hex release>/<64-hex SHA-256>/poster.(jpg|jpeg|png)`. The function also requires the creator/project scope to match the approved HLS prefix. The P2 publisher currently emits `.jpg` or `.png` and verifies bytes, SHA-256, stored `ContentType` (`image/jpeg` or `image/png`), size and server-side encryption before publication. The viewer function admits only the exact configured URI, GET/HEAD, the existing distribution host and no query string. It does not infer approval from the filename. The operator must bind the key to a *current, creator-approved immutable FREE release* through source-bound owner/project/video/artwork/rights evidence before using it as a parameter. A key for a prior, revoked or unrelated release must not be used.

This is a one-poster staging policy, not a general registry. A later requirement for many simultaneously approved artworks needs an independently designed, durable approval registry or a reviewed finite exact-key policy with explicit update/revocation semantics. Do not expand this to `delivery/**/*.jpg`, a prefix wildcard or a public S3 listing. `ApprovedFreeDeliveryPrefix` retains its exact seven-file HLS allowlist. The OAC bucket read policy still covers delivery keys only; account/bucket Block Public Access, SigV4 OAC and separate publisher permissions remain. OAC does not authorize viewers; the viewer function is the active public boundary. No paid/protected artwork or subtitle access is proposed.
