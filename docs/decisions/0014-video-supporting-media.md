# ADR 0014 — Per-video supporting media, immediate artwork and optional subtitles

Status: OWNER ACCEPTED DESIGN (2026-10-19 US Central); **PARTIAL SOURCE IMPLEMENTATION OBSERVED 2026-10-20; EXTERNAL ACCEPTANCE AND FINAL DELIVERY ARCHITECTURE NOT QUALIFIED.**
Supersedes: no earlier ADR; complements ADR 0009 immutable releases, 0011 managed VOD and 0013 free/protected access.
Implementation: [c6-supporting-media](../tasks/c6-supporting-media/README.md). Root correction version 0.6.7 unchanged.

## Problem

FireLaunch already stores uploaded/generated thumbnails as private `MediaAsset(kind=artwork, location=private_object)` references, often backed by `private/<opaque>` S3 keys. Home/Catalog's `safeArtwork()` instead reads only source/creator public HTTPS artwork URL fields; private thumbnails display as placeholders even when saved. Existing CatalogProjection and PublishedManifest v1 accept stable rights-cleared public HTTPS artwork, but have no safe private-thumbnail-to-approved-delivery bridge. The current CloudFront function and free-prefix policy admit HLS/video paths only. Forcing a creator to provide a public image URL is inappropriate. Optional subtitles are not yet represented by catalog/manifest contracts.

## Decision

1. One **logical video asset group** owns its source MP4, verified HLS renditions, thumbnail artwork versions and optional subtitle tracks. Group by existing creator/project/CatalogItem/video-asset IDs. Individual thumbnail and subtitle assets retain distinct stable IDs, identity, rights/provenance, version and lifecycle. Do not create a new S3 bucket or bulk-migrate existing `private/<opaque>` thumbnails merely for physical directory aesthetics. Continue using the existing private-object store and existing private originals/staged/delivery buckets with independent IAM/security controls. New managed keys may be grouped under validated parent paths without changing old keys.
2. **Immediate Studio display**: as soon as a custom thumbnail is selected, show a safe local blob preview; else use a successfully extracted still; else the best existing owned persisted artwork or a clear placeholder. Persist the selected/generated image at the earliest safe moment independently of encoding, without losing upload progress. After a saved image exists, render it in the video popup, Home, Catalog, upload progress, waiting/processing/failed/READY states and private channel Preview. Shared owner-scoped retrieval resolves `private_object` via the existing short-lived capability/content route, uses an in-memory Blob URL, and revokes resources on item/account/project changes; never expose a capability in an `img` URL, ChannelSpec, log, localStorage, or TV manifest. Missing/failed frame extraction remains a true fallback; no invented saved image. Prefer explicit custom artwork over extracted frames and preserve historical item references.
3. **Public artwork is an independently approved transition**: only after current owner, source provenance, artwork TV display rights, asset identity, sanitized JPEG/PNG bytes/MIME/size, and current publication/revision checks succeed may FireLaunch copy the selected artwork into immutable approved delivery storage, producing a stable HTTPS URL. Preserve previous public artwork until another approved immutable release and do not overwrite public keys; do not put private S3 keys or expiring capabilities into ChannelSpec/PublishedManifest. Existing manifest v1 already describes a public artwork URL and artwork asset binding; use narrowly scoped server-side resolution/promotion rather than adding a new incompatible TV wire shape. No automatic public promotion at upload or MediaConvert READY.
4. **CloudFront authorization is exact**, not an open image wildcard: extend the permitted suffix/types for explicitly approved JPEG/PNG paths only, plus the exact owned/versioned delivery key allowlist/manifest and a scoped publishing role. Retain private original/staged denial, OAC S3 Block Public Access, same-account creator and revocation semantics. A CDN/CloudFormation/IAM change needs separate operator authorization and reviewed change-set effects; this docs approval alone does not activate or expose new public paths. Revocation and cache persistence remain honest. Immutable release #1 remains unchanged.
5. **Optional subtitle foundation**: a subtitle track is a separate child of the parent video with stable ID, creator/project/video identity, normalized BCP 47 language tag, canonical validated UTF-8 WebVTT (.vtt), original private object identity, checksum/size, version/replace/revoke state and optional rights/provenance as appropriate. Missing captions MUST NOT block upload, encode, catalog draft, preview, FREE publication or native export. Reject HTML/script, external URLs, path traversal, malformed cues, excessive file size and duplicate same-language active tracks. Support optional private storage and a minimal Details-page uploader if safely bounded; preserve multiple languages and replacement semantics. SRT import/conversion is deferred, not silently supported.
6. **Subtitle delivery and Vega playback are deferred**. Do not add subtitle fields to strict PublishedManifest v1/ChannelSpec/native template until a versioned backwards-compatible contract and real Vega VirtualDevice caption support are independently designed and qualified. A private .vtt upload is NOT a claim that TV subtitles work. Later public .vtt requires exact immutable delivery scope, viewer policy and MIME `text/vtt`, explicit release approval and a native client capable of selecting tracks.
7. **Deadline and precedence**: P0 fix saved/new thumbnail display everywhere and P0 implement locally tested, rights-safe managed artwork public-promotion code; P1 optional subtitle data/storage/UI if bounded, but prioritize October 23 noon video pipeline/native export. Never let absent subtitles block video publication. No paid MediaConvert tests or cloud operations from this correction's runner prompts.

## October 20 source-implementation variance (provisional; not a blanket ADR reversal)

The reviewed GitHub `main` at `b0d2897eb79c6ffafe0ac394f561550cad9c0826` contains `apps/server/src/managed-artwork.ts`, `public-resolver.ts`, publication integration and tests. In that source, approved artwork is verified against an owner-scoped private object and copied to a **release-scoped immutable private-object key**, then resolved by an explicitly release-bound **Studio HTTPS** `/api/public-artwork/<deployment>/<release>/<asset>/<sha>.(jpg|png)` URL. The public resolver checks release membership, current media rights, revocation and canonical hashes. This differs materially from Decision 4's proposed **CloudFront exact JPEG/PNG allowlist and delivery-key publisher**; it is not evidence that CloudFront image policy has been activated. The old approved free HLS policy remains a separate security boundary.

**Disposition:** retain the owner's intended invariants (separate private vs explicitly approved public artwork, immutable owner/release binding, no arbitrary public image wildcard, fail-closed rights/revocation). Treat this route as a candidate simplification **pending** focused review of browser and external Vega HTTPS reachability, public-only exposure and Nginx routing, owner/foreign/revoked/unknown negative responses, authorization changes over time, object survival/rollback, request volume/performance, and approved release manifest/TV compatibility. Only after those pass should a later explicit decision formally replace the CloudFront-specific implementation requirement. If the Studio route fails these acceptance criteria, retain/fix the narrow approved CloudFront proposal rather than weakening media authorization. No new CDN/IAM/CloudFormation change or public creator publication is authorized by this note.

This is an implementation reconciliation, **not** a completed `c6-supporting-media` P6 closeout, independent device qualification, caption support or Q2 F7 GREEN. See [October 20 task routing](../tasks/c6-supporting-media/README.md) and [current state](../CURRENT-STATE.md).

## Consequences

Retain the existing private-object and MediaAsset identity model while adding a small per-video association/preview resolver and publication artwork bridge. No new default AWS bucket, FFmpeg worker, duplicate public media service, native manifest break, schema-breaking migration, automatic public exposure, speculative device qualification, or rewriting historical Q2 F7/Q3 results. Required owner-scoped tests include custom/generated/existing fallback precedence, rendering during all upload states, reload and cross-account isolation, approved artwork immutable delivery and denial before approval, prefix/MIME/path validation and failed copy, subtitle optionality/UTF-8/language validation and no wire changes.
