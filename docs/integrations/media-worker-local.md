# Local FFmpeg worker (P6 P4)

This is a manually started, single-process Linux worker. It does not start with the Studio/API and is not deployed to muffinos. It uses PostgreSQL only for private job state and S3 only for an owner-scoped verified original plus private staged HLS objects. A READY job is not a public or approved release; P6 P5 still owns rights-checked immutable delivery publication.

## Before starting

- Install Node 24, npm 12, `/usr/bin/ffmpeg`, `/usr/bin/ffprobe` and `/usr/bin/prlimit`. The offline fixture was exercised with FFmpeg/FFprobe 6.1.1; target host and native playback remain unqualified.
- Apply migrations through 012 and provide a restricted worker PostgreSQL role with only the table reads/updates/inserts used by `MediaWorkerRepository`. Keep the connection string in a root-readable operator environment file outside the repository. Do not pass a creator identity or object key on the CLI.
- Configure `FIRELAUNCH_WORKER_DATABASE_URL`, `FIRELAUNCH_MEDIA_AWS_REGION`, `FIRELAUNCH_MEDIA_ORIGINALS_BUCKET`, `FIRELAUNCH_MEDIA_DELIVERY_BUCKET`, `FIRELAUNCH_MEDIA_CLOUDFRONT_ORIGIN`, and `FIRELAUNCH_MEDIA_CLOUDFRONT_HOSTS`. Use a narrowly scoped worker IAM role for owned originals and staged delivery prefixes. Never store AWS credentials in this repository or public manifests.
- Run on a dedicated capacity-controlled Linux host with a private temp filesystem. Set an operator limit of at least 3 GiB and at most the approved worker capacity for its `/tmp`, with no other tenants sharing that volume. Restrict the service user from reading host secrets. A transient systemd unit should use `PrivateTmp=yes`, `ProtectSystem=strict`, `ProtectHome=yes`, `NoNewPrivileges=yes`, `MemoryMax=4G`, `CPUQuota=200%`, `TasksMax=32`, and `RuntimeMaxSec=15min`, adjusted only after local qualification. The process also sets FFmpeg/FFprobe CPU, virtual-memory, file-size and file-descriptor limits through `prlimit`; it kills timed-out process groups and removes its unique temp directory.

Start exactly one worker process manually with `npm run media:worker:once` from the repository root. This claims at most one job. For an operator-controlled batch, invoke `node --import tsx apps/server/src/media-worker-cli.ts --drain`; it processes serially until no eligible job remains. Do not enable an unattended timer or VPS service in P4. Capture the printed tool versions, job ID, attempt, conversion decision and terminal result in private operator logs without credentials or media bytes.

The worker accepts only a previously verified S3 original from the job's database scope, rechecks S3 metadata and full SHA-256, and caps input at 2 GB and 10 minutes. It rejects sources below 480p rather than upscaling. It remuxes a compatible 480p H.264/AAC source only when keyframe spacing and timestamps pass checks; other accepted sources use fixed H.264/AAC 480p and, if source height permits, 720p renditions. Every playlist and segment is checked before private immutable staging and the READY transition. Each lease lasts five minutes and renews every minute. An expired lease can be reclaimed; attempts cap at three. A failed upload/encode/verification leaves no READY rendition. Private staged orphans from failed attempts require periodic operator cleanup after confirming no READY rendition references them.

Focused offline check: `node --import tsx --test apps/server/test/media-worker.test.ts apps/server/test/media-storage.test.ts`. Run the PostgreSQL lease test with the existing `FIRELAUNCH_TEST_DATABASE_URL` test database when available. Real S3, CloudFront, Vega playback and public rights approval are P6 P8 qualification gates.
