# Amazon catalog feasibility for creator-owned TV channels

**Research date:** 2026-10-09. **Scope:** US-facing official Amazon documentation inspected on this date; marketplace terms and individual agreements can differ. This is a feasibility record, not evidence of FireLaunch enrollment, API access, a content license or Appstore approval. Recheck the linked terms before implementing or releasing an integration.

## Decision rule

A public seller name, author page, storefront URL, product URL, ISBN or ASIN is a **discovery clue only**. It proves neither the creator's identity nor authority to retrieve, synchronize, display or play anything on Fire TV. Record separately: source identity, retrieval permission, downstream TV display permission, and rights to each video, audio and artwork asset. A seller authorization for SP-API does not cover KDP, Audible, Associates, playback or Appstore submission. Never scrape pages or automate account login to bridge a missing API.

**Status vocabulary:** *Documented technical capability* describes an Amazon endpoint or workflow, not FireLaunch access. *Pending external approval* requires an Amazon or rights-holder decision. *Unknown/unverified* has no evidence sufficient for this use. *Restricted/blocked* must not be used in the proposed TV flow. *Planned, unimplemented* means the P1 schema exists but no live connector or importer does. No source row below is implemented or verified in FireLaunch.

## Gates before any Amazon connector or live release

1. **Amazon/provider decision:** record registration, approved app/role/marketplace and seller consent separately. Review current SP-API [policies and agreements][sp-policies] for the exact imported fields, retention and Fire TV downstream use; request written clarification where terms do not establish permission. Do not infer TV reuse from a working API call.
2. **Creator decision:** verify source ownership and explicit permission to import; review each ambiguous match; document television display and separate playback/artwork rights. For Audible/ACX, check the title's actual distribution agreement.
3. **FireLaunch decision:** only enable an adapter after documented authorization, secure token handling, provenance, revocation and rights gates are implemented and tested. New items enter review, missing items receive grace/review, creator overrides survive sync, and public manifests contain no secrets or unlicensed media.
4. **Publisher decision:** the creator owns the independent app, Developer Console listing and submission; actual Appstore approval is a separate later gate. [Amazon submission][appstore-submit]

## P2 and later handoff

P2 must enforce per-creator ownership/authorization in storage and APIs, globally unique package identities, private evidence/token storage and safe export/deletion. P1 Zod parsing does **not** authenticate a user or prove a consent record. P3 should implement file/feed import first with stable source-scoped IDs, duplicate review and media rights, leaving Amazon adapters unavailable. P4 AI may consume only reviewed, permitted catalog context through validated ChannelSpec mutations. P5 may publish only approved TV-safe manifests; P6 may sync only permitted sources with creator override and revocation rules. P7/P8 own truthful creator submission and real Appstore/device evidence. See [creator onboarding](../creator-onboarding.md) and [roadmap](../roadmap/mvp-roadmap.md).
