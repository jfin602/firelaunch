## Exact normal-mode composition

1. **Main global navigation** remains at far left; immediately beside it is the **secondary left Channel editor rail** with Pages & Layout and Appearance. **No gap or misaligned inset seam** between the two vertical bars. Each still has a discernible subtle divider for navigation/a11y hierarchy. The header/topbar is aligned with the columns below, with unnecessary Channel-only outer padding removed. Retain global navigation/identity and status functionality.
2. **Neutral tool palette**: the editor rail, page rows, section cards, tabs and forms should adopt the same **dark/neutral charcoal gray family as the actual New Page popup**, not the former warm brown panel background. Deliberate accent orange is for selected/primary controls; destructive states retain meaningful risk color; focus remains visible. Do not recolor the creator TV brand or thumbnails.
3. **Channel workspace background**: the existing very-dark preview-stage background (near-black/charcoal) spans ALL of the Channel work area, behind both editor and TV. On Channel only, the scenic canyon image must be entirely hidden behind the continuous solid surface; no scenic fragments along top, seams or margins. Other Studio surfaces continue using their prior visual system.
4. **Right TV Preview** is the visual focus. It occupies the **maximum safe upper-right 16:9 rectangle** available in the right preview column, bounded by actual width AND height. No decorative TV bezel, outer card border, extra shadow, or thick frame. Never crop, stretch or fake 16:9 by distorting video content. The app's own intentional content boundaries/navigation remain untouched. The TV touches its allocated container edges where the geometry permits; letterboxing only where required by aspect ratio.
5. **Controls live below TV, not above it:** in the remaining lower-right space, put a compact row with `Draft TV Preview`, green `16:9 · Interactive` indicator, and a styled `View full screen` button. The Virtual remote stays a separate bottom/right controller BELOW the actual TV, not superimposed on frame or video. Use this space without gratuitous panels or dead margins. Keep keyboard/remote help legible and visually subdued.
6. **Viewport responsiveness**: desktop reference ~1440×900 and ~1280×720; tablet and phone remain operational via c8-ui2 adaptations. No whole-document vertical or horizontal scroll on ordinary desktop merely from padding/frame/control placement. Long editing content scrolls only inside secondary rail. Small screens prioritize real TV aspect, reachable metadata/fullscreen/remote, and usable controls; allow deliberate contained scrolling when truly necessary.

## True fullscreen / Clean View extension — owner-approved 2026-10-21

**The normal Channel mockup above remains unchanged.** Fullscreen is a separate immersive mode with THREE states and no permanent Studio chrome.

1. **Controls visible (default fullscreen):** the actual TV app fills the largest 16:9 rectangle in the real viewport, **edge-to-edge on a 16:9 screen**. No border, shadow, padding, stage header or remote/footer reservation. Only unavoidable letterbox bars use the same dark background. The **Virtual remote floats over BOTTOM LEFT**, while a compact **TOP RIGHT overlay contains Exit full screen and Hide controls**. Do not preserve the normal-mode below-TV remote/status row in fullscreen. TV Back remains separate from fullscreen Exit.
2. **Editor open:** the EXISTING secondary editor appears as a LEFT slide-out overlay over the app, with hover/touch/keyboard reveal and unsaved-input focus protection. This is the same editor instance from normal mode, not a cloned control panel or second TV. Remote remains bottom left and Exit/Hide top right until Clean View.
3. **Clean View (Hide controls):** display **ONLY the creator's TV app**. Hide top-right controls, bottom-left remote, left editor drawer and reveal handle, metadata, status, help and ALL Studio-only overlays. There should be no permanent visible affordance or invisible layer covering TV interaction. Fullscreen remains active; TV D-pad, focus and playback continue unchanged. Keyboard H toggles clean/control mode when not editing a text field; an intentionally small TOP RIGHT corner recovery zone can reveal controls on pointer hover/touch, while normal pointer movement over the TV must not reveal controls. **Alt+E** exits Clean View and opens the existing left editor; **Escape** exits fullscreen from any state. Do not consume character keys inside inputs, disable accessible recovery or trap touch/screen-reader users.

**Actual fullscreen source constraints:** `apps/studio/src/App.tsx` owns `previewFullscreen`, shared `fullscreenRoot`, `dockVisible`, `dockHover`, keyboard/fallback/inert logic; `Preview.tsx` contains `.preview-heading`, `.tv-frame` and `.remote-bar`; existing CSS has `.preview-fullscreen .tv-frame` height deductions and padding. The new P3 must reuse them, adding only bounded overlay visibility state. Do not create a separate Preview instance, re-mount the VideoPlayer, or resize full-screen TV to accommodate overlay controls. Restore editor scroll, focused TV item, video playback state, clean-mode reset and focus to Full Screen trigger on exit. Browser denied Fullscreen API must be visibly distinguished from native fullscreen and tested as fallback.

**Qualification additions:** in the **deployed staging** Codex browser check controls-visible/fullscreen TV geometry, remote bottom left, Exit/Hide top right, left editor drawer, Clean View app-only screenshot, recovery via H/top-right zone/Alt+E/Escape, touch emulation and narrow viewports. A fallback-only test does not qualify native-browser fullscreen. The updated `c8-ui3` sequence is P1 shell, P2 normal Preview, **P3 true fullscreen/Clean View**, **P4 manual protected-deploy-first visual closeout**. The runner must stop before P4. Root/lock stays `0.8.10`, Phase 8 stays OPEN.
