# C8 Hero Multimedia — Focus-Driven TV Hero

**Owner-approved design contract — 2026-10-22.** Applies to the existing `snabble tv`/creator-owned Vega TV app, not the FireLaunch Studio marketing UI. Four bounded prompts in [c8-hero-multimedia](../tasks/c8-hero-multimedia/README.md). This is the modernized version of the **actual simple native app** shown by the owner: horizontal title/navigation at top, one featured hero area and **one horizontal content row within the first 16:9 screen**, with minimal surrounding chrome. Do not reproduce invented FireLaunch TV sidebars, a three-panel comparison montage or a full visual retheme.

## Interaction is the product

- **Top = contextual featured display; bottom = focusable selector.** The content displayed in the hero changes as the viewer moves remote D-pad focus among the cards in the **one row directly below** it. Selection on a card is *focus*, not playback: **Select/Enter** opens that exact item's existing detail state; an additional Select on its permitted Play/Listen action enters playback; Back returns to the selected bottom card, restoring focus and the selected hero. No automatic playback on focus.
- **One selector row is visible without page scrolling** at standard HD/FHD TV viewports. Top navigation and the hero + first row fit into 1280x720 and 1920x1080 safe areas. Horizontal overflow for additional cards is navigated by D-pad and may scroll horizontally; there is no forced vertical scrolling to see the first row. Additional authored modules below the hero remain valid and reachable with deliberate scrolling/navigation; **do not delete or truncate page content** just to make the screen fit.
- Default featured item comes from the first eligible **authored Hero/first relevant row selection**, with deterministic fallback to the first visible selector item. Avoid duplicate cards if the existing one-item Hero and first populated rail reference the same item. If either side is empty, show a quiet honest empty state or safe normal module fallback rather than fabricate media. Changing pages or manifest revisions safely reconciles invalid IDs and never selects off-page, foreign or revoked content.
- Preserve one canonical `ChannelSpec`, existing `hero|rail|grid|text|image-banner|image-text` module schemas, creator ordering, custom page data, Live-vs-draft boundaries and one shared `packages/tv` focus/transition model. Implement as a **derived presentation** on eligible Hero-template pages (first appropriate `hero` with adjacent populated `rail`/compatible selector), not as a new saved page type, second TV engine, schema migration or global replacement of Rows/Grid pages. Static informational sections remain display-only and should not become focusable hero item cards.
- Top hero reflects focused title, description, category/year/artist/author/series metadata **only when present and eligible**, and a media-appropriate action label; book-only displays **Explore / Details**, not Play, and optional audiobook displays **Listen to Audiobook** when rights-eligible. Standalone audio displays Listen, video displays Watch. Existing native details/player/Back controls are the actions, not an extra playback overlay invented inside the hero.
- Native and Studio Preview must give the same selected item, ordering, focus, artwork mode and fallback. The persistent horizontal navigation and standard keyboard/directional semantics stay intact; focused card has a restrained brand-accent outline that clearly shows selection.

## Adaptive creator-artwork background

- Use the **same authorized existing item artwork** as both the sharp cover/poster and an optional atmospheric backdrop. **Never require or generate a second cinematic image.** For landscape film artwork, wide photo can fill hero with a scrim; for square album art, show full crisp 1:1 cover and dark/blurred derivative behind; for 2:3 portrait book cover show full uncropped poster with darker/blurred derivative. Avoid stretching, clipping important poster text or false stock artwork. Foreground `resizeMode=contain` when necessary, controlled `cover` solely for expendable background.
- Use a deterministic, bounded two-layer implementation with existing `Image`/CSS and brand-neutral gradient/dark scrim; actual `blurRadius`/gradient support, Vega SDK compatibility and performance must be observed rather than assumed. Native resource/memory limits matter: limit image dimensions, eliminate redundant loading and use a static dark scrim or brand-gradient fallback if blur is unsupported/slow/low-res. Do not introduce costly image generation, new AWS pipelines or public media derivatives in this correction.
- Keep hero generally **40-50% of the actual screen height**, adapting to 720p/1080p and content safely so header and first row remain visible; avoid absolute unresponsive pixel assumptions. Atmosphere fades toward the first row and into the channel's own dark/neutral background, **not** the FireLaunch Studio Desert Heat theme. Preserve creator's primary, background and text colors with readable contrast; don't hardwire FireLaunch orange to every TV channel.
- Use only source-approved publication-safe HTTPS artwork for generated native/public Vega. Studio may resolve an authorized private owner-only artwork preview through its existing secure asset resolver; **never serialize private blob/capability/S3-original URLs into ChannelSpec, a published manifest or exported package**. Handle missing/revoked/invalid images with a text-readable neutral fallback. Do not change source/display-rights policy to make the image load.
