# P6 P8 operator proof — not yet executed

This is a **manual** checklist for the independent `0.6.8` gate, not an instruction to provision AWS during P7. Preserve [deferred P5/c5 qualification](deferred-qualification.md) and their historical NOT GREEN closeouts. Record each check as PASS, PARTIAL or BLOCKED with timestamp, redacted evidence and exact tested commit. Stop on missing ownership/rights, authenticated staging, dedicated public origin or trustworthy device evidence. Never expose credentials, private source bytes, signed URLs or full session cookies in logs.

## Approval and safe infrastructure

1. Obtain explicit operator approval for AWS account, region, spend ceiling, source-master and artwork license, TV **display and playback** permission, and public free-to-view publication. Discovery/ASIN, an upload or a successful encode is not rights clearance. Record creator account/project/deployment, channel/catalog revisions, evidence references and revocation owner privately. Use an independent second Google identity to test tenant denial. Check migration 010 (P5), 011–012 (P6), current HEAD/version, backups and rollback readiness. Take Ngest's owner-approved HTTPS health response and process/service-state snapshot *before* changes; do not restart, reconfigure or deploy Ngest.
2. On the operator workstation inspect [the reviewed CloudFormation proposal](../../../infra/aws-media/README.md) and `infra/aws-media/template.yaml`. Check least-privilege same-account trust and separate uploader, worker and publisher roles: uploader multipart/HEAD/abort only on scoped private originals, worker read verified originals and write staged, publisher read staged and conditionally write delivery, CloudFront OAC read **only delivery** under exact distribution ARN. No root or long-lived shared access key, public ACL, S3 website origin, unrestricted bucket listing or cross-account trust. Confirm Block Public Access, bucket-owner ownership, encryption, incomplete-multipart lifecycle, logging and retention. S3 CORS permits the exact HTTPS Studio origin, PUT and exposed ETag; it is not an auth boundary. Review the CloudFront HTTPS certificate/host allowlist, GET/HEAD-only behavior and cache/error TTL against `infra/aws-media/template.yaml` and current AWS documentation.
3. **After approval only**, use the operator's named profile and reviewed parameter values to validate and preview the template before deciding whether to apply. Replace placeholders locally; do not check in parameter files or execute a change set until independently approved:

   ```sh
   aws --profile "$AWS_PROFILE" --region "$AWS_REGION" sts get-caller-identity
   aws --profile "$AWS_PROFILE" --region "$AWS_REGION" cloudformation validate-template --template-body file://infra/aws-media/template.yaml
   aws --profile "$AWS_PROFILE" --region "$AWS_REGION" cloudformation create-change-set --stack-name "$STACK" --change-set-name "$CHANGE_SET" --change-set-type CREATE --template-body file://infra/aws-media/template.yaml --parameters file://"$PRIVATE_PARAMETERS" --capabilities CAPABILITY_NAMED_IAM
   aws --profile "$AWS_PROFILE" --region "$AWS_REGION" cloudformation describe-change-set --stack-name "$STACK" --change-set-name "$CHANGE_SET"
   ```

   If updating an existing reviewed stack, use `UPDATE`, not `CREATE`. Confirm no collateral changes and require a second approval for `execute-change-set`. Query the deployed distribution/OAC/bucket policies and account Block Public Access. Anonymous `curl` to S3 originals and staged/delivery S3 URLs must fail; staged CloudFront URLs must fail, while only an approved delivery object should return 200. Keep object paths and signed capabilities out of the report. Check actual `Content-Type` for `.m3u8` (`application/vnd.apple.mpegurl`) and `.ts` (`video/mp2t`), HTTPS certificate, CORS preflight/ETag and playable segment graph. Set AWS Budgets cost/usage notifications and CloudWatch/CloudFront/S3 metrics before uploading; alerts are delayed and **not** hard spend caps. Record observed storage, request counts, transfer and invalidation costs, not a guessed free-tier price.

## Staging and local worker

4. Verify the separate public-only TV HTTPS vhost from [P5's staging checklist](../p5/public-https-staging.md): exact `/tv/v1/deployments/.../current` and `/releases/...` GETs only, no Studio, `/api`, private files or mutation routes. Do not put the private Studio host into a TV package. Keep server-only `FIRELAUNCH_MEDIA_AWS_REGION`, `FIRELAUNCH_MEDIA_ORIGINALS_BUCKET`, `FIRELAUNCH_MEDIA_DELIVERY_BUCKET`, `FIRELAUNCH_MEDIA_CLOUDFRONT_ORIGIN` and `FIRELAUNCH_MEDIA_CLOUDFRONT_HOSTS` outside Git, using short-lived assumed-role credentials. Check `infra/aws-media/README.md` for expected exact host and IAM roles.
5. Deploy the *reviewed* release archive using `scripts/staging/build-release.sh` and `scripts/staging/deploy-release.sh` only after verifying its SHA-256 and inspecting its content; hosted native build remains disabled. For password-only SSH, configure the operator's local `~/.ssh/config` entry for `muffinos` with `PreferredAuthentications password`, `PubkeyAuthentication no`, `BatchMode no`, `StrictHostKeyChecking yes` and a preverified host fingerprint, then run `ssh deploy@muffinos 'test -d /srv/firelaunch-staging/releases'` and the deployment script. It uses `ssh`/`scp` and prompts locally; **no remote Codex/agent, password file, sshpass, SSH policy change, or credential capture**. Verify remote migration/health, monitor server logs with secrets redacted; restore the previously verified release with `scripts/staging/rollback.sh` if staging health fails. Do not roll back immutable published channel history by changing old bytes.
6. On a separate capacity-limited Linux Mint host follow [local worker instructions](../../integrations/media-worker-local.md): Node 24/npm 12, `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`, `/usr/bin/prlimit`, private temp volume and least-privilege worker DB/S3 role. Record tool versions and disk/memory limits. Manually invoke `npm run media:worker:once` from the checkout with a private `FIRELAUNCH_WORKER_DATABASE_URL`; never run untrusted FFmpeg flags or transcode on muffinos. One serial claim at a time; inspect verified upload SHA-256, lease/retry, 480p/720p where source allows, master/variant/segments, alignment, MIME, hashes and READY. Failure or expired lease must not become READY. Do not grant the worker publisher permissions.

## Creator, publication and same installed Vega client

7. In an authenticated creator Studio session (normal CSRF-bearing UI), create an owned source, video item and media asset; review import provenance and separate TV playback/display rights. Direct-upload a short independently licensed MP4 to **private S3**, confirm browser progress and HEAD/full SHA-256 on worker, owner status and foreign-owner/session denial. Test expired/aborted upload, malformed type/path/size, failed part/finalize, processing or revoked asset rejection without bypassing CSRF. READY is still a private draft. Select a licensed public HTTPS artwork asset, bind the managed HLS asset, confirm current catalog/channel revisions and readiness, **explicitly approve** and publish v1 through private P5 Publish. Confirm CloudFront master, variants and every segment over HTTPS, public resolver pointer/release SHA-256 and no transcript, credentials, source/evidence IDs, S3 keys, signed capabilities or owner data in source/export/release bytes. Historical release bytes are immutable; foreign, stale, processing and revoked media must not publish or resolve on fresh requests.
8. Follow [c5's device checklist](../c5-vega/device-runbook.md) on a **fresh owner/deployment-bound VPKG** generated with the dedicated TV HTTPS origin. Record Vega CLI/SDK/VirtualDevice OS, Release build result, package hash and **one install** (`vega device install-app --device VirtualDevice --packagePath "$VPKG"`), then `vega device launch-app --device VirtualDevice --appName "${PACKAGE_ID}.main"` after checking the installed CLI's help. Test v1 focus/detail/Back and HLS start/pause/seek/recovery on that installed app; capture device requests, screenshots and redacted logs, not website playback. Approve and publish a meaningfully changed v2 from the same creator; check sequence 2 and visible refresh **without rebuild/reinstall**. Disconnect, cold-restart and prove verified v2 last-known-good. At an isolated test origin only, inject bad JSON/hash, wrong deployment/schema, 404/5xx/timeout and confirm rejection plus usable v2; restore the real origin and verify recovery. Never corrupt real immutable DB release bytes or shared CDN objects to create a fault.
9. Recheck current rights, explicitly approve rollback of v1 and publish **new** v3. Confirm sequence 3, new release ID, `previousReleaseId=v2`, `rollbackSourceReleaseId=v1`, unchanged v1/v2 bytes and same installed app returning to v1. Verify fresh resolver denial after revocation, then use the guarded operator invalidation only if approved (see [media delivery runbook](../../integrations/aws-media-delivery.md)). Cache TTL, CDN edge, player cache and offline LKG can outlive the server's rights decision; never promise instant erasure. OAC gives public free viewers access through CloudFront, **not** paid entitlement. Future signed cookies/URLs and DRM require a separately qualified native player/entitlement design, not expiring secrets in PublishedManifest.

## Exit and teardown

10. Repeat the *same* Ngest health URL/process check and compare with baseline. Capture tenant/CSRF negatives, release IDs/hashes, playlist/segment MIME and direct S3 denial, CloudFront requests/TTL, budget state, VirtualDevice OS/package hash/install count, v1/v2/v3/fault/offline evidence. Redact credentials and media. On failure, stop uploads/publishing, restore controlled fault origin, use the previously verified staging release, and reconcile S3 multipart/orphan staging, CloudFront invalidation state, DB jobs and published rights before retrying. For temporary AWS resources, require operator approval, inspect current use and retention/backups, review CloudFormation deletion impact (stack deletion is destructive), then manually remove only confirmed disposable test artifacts; never delete production or creator-owned data merely to clean up a test. If any live AWS/rights/identity/HTTPS/device gate is missing, P8 writes **NOT GREEN** with actual observations; mock results do not upgrade P5/c5 or P6 qualification.
