## P1 — Shared focus selection

Compute hero display item from existing projected page's Hero and first appropriate rail/grid. The **one focusable selector row** is the first row associated with a Hero; include a one-item Hero candidate without duplicate cards where feasible, but do not break existing persisted modules or visual order of downstream sections. If row empty/missing, cleanly fall back (ordinary modules or one-item hero). Preserve page+card+focusId in TV transition; highlight the exact selected bottom card and update contextual hero when focus moves using existing `up/down/left/right` routes, without opening details. Select opens selected item's detail; Back returns to the same page/card and leaves hero on it. Invalidate selection after page changes, item deletion, project/release update or catalog revocation, never a stale/private content title. Keep old v1 data parsed as-is, no stored featuredItem field and no migration.

## P2 — Studio hero view

Do not generate new mock media. Render the selected spotlight as a top hero content region (title/description/metadata/action label), sharp existing artwork in suitable natural frame, atmospheric background via same authorized owner image with gradient/scrim where possible. 16:9 landscape: background crop only; square album: crisp 1:1; portrait book: crisp uncropped ~2:3. Cover can be `contain`, background may be `cover` and dimmed/blurred. If source missing/revoked, neutral readable fallback; don't leak secure blob/signed URL into spec. Fit nav + hero (roughly 40–50% frame height) + ONE visible row at 1280x720 and 1920x1080; no forced document/page vertical scrolling to reach first row. Other creator sections stay safely scrollable. Keep Preview as same mounted instance with remote, fullscreen Clean View, save/edit/focus and current video/audio/books. Use CSS limited to the TV component, not Studio global branding.

## P3 — Native Vega

Implement matching hero+selector presentation as a derived special-case view only for eligible Hero pages in `App.js`. Use shared `packages/tv` functions; keep native React Native Image/TVEventHandler instead of invented browser CSS API. Verify SDK support for optional blur/gradient, otherwise use darkened brand-tinted overlay and deterministic safe fallback. Limit photo memory and re-renders on rapid D-pad input. Update `tv-layout.js` using actual height/width safe-inset metrics so header + hero + row fit at both HD/FHD. Maintain navigation ScrollView and focus, while preventing scrollTarget from pushing selected first row out of initial view. Don't overrule creator's other modules and no invasive HLS/audio/rights changes. Test remote focus, select detail/Back, page switching, revoked/missing art, renderer projection/build and performance-oriented fallback. No actual publication or new MediaConvert.
