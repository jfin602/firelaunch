IMPLEMENT
1. **Actually full screen:** While fullscreen or its truthful viewport-covering fallback is active, hide all NORMAL Studio Preview metadata, under-TV toolbar, frame border, shadow, padding and artificial height reservation. Fit .tv-frame as min(viewport width, viewport height*16/9) by min(viewport height, viewport width*9/16), centered/letterboxed but never cropped or distorted. On a 16:9 viewport the real TV occupies all available screen area, with no permanent black gutters or editor strips. The native browser Fullscreen API must be requested from the user's direct gesture; do not claim native success when browser denied and fallback used.
2. **Control-overlay mode:** On entry show a compact Virtual remote overlay at BOTTOM LEFT and an unobtrusive accessible TOP RIGHT control cluster with Exit full screen and Hide controls. The existing editor stays hidden except when the user opens the LEFT edge drawer. All overlays must be within the fullscreen root, and should float above TV without reflowing or shrinking the 16:9 TV. Remote still supports D-pad/select/Back; Escape exits fullscreen while Backspace or the virtual remote provides TV Back outside editable fields. Keep overlay typography/icons readable.
3. **Clean View:** Hide controls explicitly toggles a single Clean View state that hides the entire Virtual remote, top-right Exit/Hide cluster, editor drawer, editor reveal handle, preview heading/status and any other Studio-only chrome. NO visible handle or permanent invisible overlay may cover app interactions. The TV continues rendering and receiving TV input with identical state/playback. A screen reader should not encounter hidden controls as active focus targets. Do not hide creator app navigation, subtitles or real app content.
4. **Recoverability without spoiling Clean View:** Press H (except inside input/textarea/select/contenteditable or browser-modified shortcut context) to toggle controls. A small top-right CORNER activation zone by pointer-hover/click or touch tap can reveal controls, without showing overlays on ordinary pointer movement elsewhere. Alt+E exits Clean View AND reveals/focuses the existing LEFT editor drawer, which otherwise is disabled from auto-reveal in Clean View. Escape exits fullscreen EVEN with Clean View active; after exit restore normal editor UI, focus on the entry trigger, original scroll and clear Clean View. Do not trap keyboard/touch users or cause the TV's real remote navigation to steal text entry. Document a concise shortcut hint before initial hide if needed, without adding permanent chrome.
5. **Existing LEFT drawer:** With controls shown, hovering/clicking LEFT edge still reveals the SAME editing component, with current focus/unsaved hold and idle-hide logic. In Clean View all editor overlays/handles remain hidden unless Alt+E or explicit Show controls action is invoked. Exiting Clean View restores ordinary reveal behavior but must not duplicate/remount the editor or Preview. Preserve fallback inert handling so interactive controls inside shared root are never disabled. Keep reduced motion, fullscreenchange, project switch and unmount cleanup safe.
6. **Source scope:** Prefer a small `fullscreenUiMode`/visibility state in existing App.tsx with narrowly scoped fullscreen CSS and minimally adapted Preview.tsx props/structure. Avoid second fullscreen state machine, new Preview/player instance, portals, global body styles or any ChannelSpec/renderer changes. P1/P2 normal mode must remain visually unchanged.
