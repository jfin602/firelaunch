## Root cause and repair

The replacement created a new READY rendition set for the same owned video asset, but the saved ChannelSpec still contained the prior rendition's delivery URL. `PrivateVideoPreview` required the latest set's URL to equal that saved URL, so authenticated Preview rejected the replacement. Optional subtitles only changed `video_subtitle_tracks` and private `text/vtt` objects.

`apps/server/src/private-video-preview.ts` now verifies that the saved URL exactly matches a non-revoked READY rendition of the same owner/project/item/asset, with a verified upload, then serves the latest READY set. It retains source permission, asset rights, lifecycle revocation, exact playlist/segment allowlisting, SHA-256 checks and owner-scoped access. A failed latest job still blocks playback. No public delivery path is used for private Preview. `apps/server/test/private-video-preview.test.ts` covers replacement, foreign access, mismatched URL, revoked prior binding and failed latest job. The saved draft URL itself remains prior-version data; a future creator-approved export/publication must intentionally refresh that binding.
