## P1 — Private thumbnails everywhere

Source: apps/studio/src/{VideoUpload,Catalog,Home,Preview,artwork-url,api}.tsx/ts, image helpers, tests. Prioritize owner-uploaded selected image, then extracted still, then linked saved thumbnail and valid legacy source art, then fallback. Show early during file selection/upload/processing irrespective of MediaConvert state. Bind saved artwork to current creator/project/CatalogItem and read existing private_object via authenticated 60s capability and binary content route; use fetch blob URL (revoke and abort on unmount/change), not capability in image src. Use one shared resolver/component without leaking private keys/capabilities. Private channel preview needs owner-only visual overlay/approved Studio-only lookup; no private object in canonical public/exportable ChannelSpec. After reload/close, load owner-backed data and maintain thumbnail; custom over generated; no data rewrite. Address old existing thumbnails without reupload. Focused tests and Studio build. Leave public promotion to P2.

## P2 — Server-approved image delivery and publication resolver

Source: apps/server/src/{media-storage,publication-repository,catalog-projection,private-objects}.ts, packages/contracts/src/publication.ts as narrowly needed, tests. Safely validate creator-owned image object, its separate artwork MediaAsset and image rights/source provenance; use approved separate publisher role to write immutable SHA-256 versioned JPEG/PNG under owned video delivery scope, preserving private S3 storage and no public writes from control role. Review/preview resolves deterministic future public URL without mutating anything, publish promotion rechecks current owner/catalog revisions/rights + exact bytes/hash and ties to release. Similar existing resolvedPlayback mechanism may become narrowly generalized to resolvedMedia URLs. Existing PublishedManifest v1 asset kind=artwork/url remains strict and compatible; no secret/signed/private URLs or automatic publication at upload. On failure no pointer update; idempotent retry, old release untouched. Focused local fake-S3/provenance/negative tests, affected server/contract build. Do not execute AWS CloudFront changes here.

## P3 — Exact CDN image permit, review-only cloud proposal

Source: infra/aws/staging/cloudformation/02-firelaunch-staging-foundation.yaml, infra/aws-media, IAM/publisher tests, server media-storage URL matching tests. Audit currently exact HLS-prefix free allowlist and functions; design bounded exact immutable *approved image* allowlist/path validation linked to creator/release identity, with JPEG/PNG content type, OAC private S3, no public ACL and no broad 'all jpg in delivery' bypass. Keep old HLS prefixes/release #1 and old function semantics. Add review-only template and focused template tests for allowed approved image, denied unapproved/foreign/original/staged/malformed/traversal, unknown paid source and no extra public distribution. If implementation would require an incompatible large policy expansion, stop with safe review-only proposal, not broad allow. No executing AWS change set in this correction; operator approval and live 403/200 evidence still required.

## P4 — Optional private subtitle track foundation

Source: small server/contracts/catalog record and/or migrations only if additive backward-compatible and safe, Studio per-video Details, related tests. Define separate track ID and parent CatalogItem/video identity + normalized BCP 47 language, UTF-8 WebVTT MIME/bounded size/cues/lines/URLs/script rejection, checksum, private stored object, revision and replacement/deletion. Permit multiple language tracks; prevent duplicate live track for same language. One optional upload control on Details if bounded, otherwise document the contract and defer UI. Never require subtitles; no new strict manifest v1 fields/ChannelSpec/native Vega changes, no new S3 bucket, no public .vtt allowlist or claimed TV subtitle support. Existing private object quota and owner checks remain; assess required additive schema migration and whether deploy would need separate schema-recovery approval. Focused tests, no paid work.

## P5 — UX and compatibility convergence

Verify immediate/reloaded thumbnails in Home, Catalog, video popup, in-progress/processing/READY/failed, owner-private preview and source priority. Verify no upload/MediaConvert dependency, correct object URL cleanup, no secret leakage, real asset identity and safe image publication pipeline. Verify failed/corrupt/out-of-scope images fail to placeholder rather than public leak. Subtitles missing keeps every draft/release valid; private tracks never get into TV manifests. Ensure source/P5 immutability, existing released HLS, stage/public segregation, revision mismatch and presentation remain intact. Targeted affected Studio/server/contract tests/build and diff check; do not do redundant global runs.

## Dependency order and invariant

P1 private visibility independent of MediaConvert -> P2 approved immutable image delivery -> P3 secure CloudFront capability proposal -> P4 optional subtitle foundation -> P5 UX convergence -> P6 real browser/independent closeout. Source repair/update isn't a cloud deploy. No AWS changes or customer upload processing without explicitly approved separate operator workflow. Never clobber concurrent c6-usability or prior playback repairs. Preserve root 0.6.7, prior releases and Q2/Q3 status. Target <=8 minutes per implementation, 15-minute hard cap; stop with bounded blockers rather than broad unreviewed change.
