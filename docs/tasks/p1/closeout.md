## Contract findings

- `CreatorAccount`, public `CreatorProfile`, `ChannelOwnership` and `ChannelDeployment` are strict versioned shapes. The registry checks account/project/channel/deployment references and duplicate app package identities **within one supplied snapshot**; deployment explicitly gives native release control to the creator. P2 must authenticate users and enforce cross-tenant authorization plus global uniqueness transactionally. A Console evidence ID or creator report is a recorded claim, not independently verified Amazon approval.
- `CatalogItem` admits books/listings with an empty `mediaAssetIds` array. Source records retain a source ID, namespaced provider/marketplace/kind/value and original metadata apart from creator overrides. `MediaAsset` separately records TV display/playback rights, evidence status and delivery eligibility; a listing or ASIN does not grant playable media rights. Inventory parsing checks local scope and references, but provider consent and rights evidence require later verification.
- `SyncPolicy` fixes new items to review, missing items to a 24–2160 hour grace followed by review, creator field preservation, conflict review and revocation suspension. `validateSyncDecision` rejects attempts to overwrite creator fields or mismatched source/item scope. P6 must actually schedule grace, deduplicate events, reconcile and stop retrieval on revocation.
- `publicationDraftSchema` cannot feed `projectApprovedManifest`. The projector checks approved scope, bound catalog items, eligible TV-cleared media, verified/authorized source assertions and public HTTPS media; `publishedManifestSchema` rejects private/unknown fields, unsafe URL forms and inconsistent references. Client compatibility is fixed to schema v1. P5 must enforce approval transactions, immutable release storage, client activation, last-known-good fallback and rollback; schema parsing alone does not prove any of these runtime properties or validate the truth of a rights assertion.
- Historical `ChannelSpec` v1 and local `projectSchema` fields were not edited; only new exports were added to `packages/contracts/src/index.ts`. The P0 fixture still parses, and generator tests in the root check still exercise deterministic Vega source, manifest and TV projection. P2 must migrate real local project data deliberately; fixture compatibility is not a hosted-data migration test.

## Amazon and onboarding audit

The dated [feasibility matrix](../../integrations/amazon-catalog-feasibility.md) separates documented API operations from account approval, seller consent, downstream TV use and media rights. This review rechecked Amazon's official [SP-API onboarding](https://developer-docs.amazon.com/sp-api/docs/onboarding-overview), [role guidance](https://developer-docs.amazon.com/sp-api/docs/roles-in-the-selling-partner-api), [Listings Items operation](https://developer-docs.amazon.com/sp-api/reference/searchlistingsitems), [Catalog Items API](https://developer-docs.amazon.com/sp-api/docs/catalog-items-api), [Notifications API](https://developer-docs.amazon.com/sp-api/docs/notifications-api), [KDP Bookshelf](https://kdp.amazon.com/en_US/help/topic/G200672810), [Author Central](https://kdp.amazon.com/en_US/help/topic/G200644310), [Creators API](https://affiliate-program.amazon.com/creatorsapi/docs/en-us/introduction) and [US Associates policies](https://affiliate-program.amazon.com/help/operating/policies/). The cited ACX help URLs reached a thin page shell during this review, so Audible/ACX catalog/API and title rights remain expressly unverified. No source is described as enabled in FireLaunch.

SP-API public developer registration, approved roles, public-app OAuth and seller authorization are distinct prerequisites. Listings/Catalog Items and notifications offer technical operations, but the reviewed material does not grant independent TV redistribution or playback rights. Public KDP/Author Central and Audible material does not establish a universal FireLaunch connector. Current US Associates restrictions prohibit Program Content and links in the proposed TV set-top-box flow; Creators/PA-API are not an import fallback. Creator-controlled CSV/JSON, HTTPS feeds and licensed media are the documented first-party fallback, still subject to provenance and rights review. Amazon approval, specific TV field reuse, seller consent and each asset license remain open human/policy decisions.

The proposed [creator onboarding flow](../../creator-onboarding.md) gives video, audio and writing creators a catalog-first no-code path through source identification, ownership and rights review, import/match, curation, licensed media, draft generation and TV Preview. It includes ambiguous match, empty catalog, unsupported/denied API, unsafe media and file/feed error states; prompt-first is an alternative. This is a specification, not implemented UI or a live importer.
