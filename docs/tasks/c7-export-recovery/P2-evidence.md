## Implemented local contract

- `native-worker-protocol.ts` signs an immutable `ReleaseBuildInput` claim with the API Ed25519 key, binds job ID, one of three attempts, 256-bit nonce and a window of at most 15 minutes. The separate worker verifies it with the API public key. The result receipt binds the full claim hash, worker ID, nonce/attempt, exact `NativeBuildEvidence` and completion time, signed by the worker key. Acceptance verifies both signatures, expiry, cancellation, current owner/project/deployment/release/source fingerprint through a required callback, native evidence, VPKG bytes and an atomic one-time claim consumption callback. The callbacks are intentionally not wired to hosted routes until P3 implements a durable owner-scoped job store.
- `native-worker-runner.ts` is a worker-side execution adapter. It has **no default isolation assertion** and is not reachable from `firelaunch-staging.service`. It rejects root execution, inherited control-plane credential environment names, unpinned toolchain identity and unsafe worker configuration. It reads cgroup v2 CPU (at most two cores), memory (1–8 GB), process (at most 256) and dedicated filesystem size (1–20 GB) before running. After an independently supplied isolation check, it uses a private disposable workspace, fixed producer commands without a shell, a small allowlisted child environment, bounded output/deadline, process-group termination, fresh VPT-inspected x86_64 Release artifact verification and cleanup. It rereads and hashes the artifact before signing. The runtime does not itself prove secret-free mounts, actual npm/SDK binary provenance or egress controls; the required isolation assertion must be backed by direct operator checks on the separate host.
- Existing `release-build.ts` rejects unsafe/oversized paths and contents, symlinks, source/hash drift, stale output, wrong VPKG package/OS and unverified toolchain identities. Existing `native-export.ts` verifies the four-file ZIP, source/deployment/release evidence and package byte hash. A synthetic 2 KiB fixture in tests is **unit evidence only**. No real VPKG SHA or worker logs exist in R2.
