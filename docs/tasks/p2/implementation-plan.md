Authority: roadmap P2; docs/ARCHITECTURE.md and PRODUCT-MODEL.md; ADRs 0001, 0004–0008; P1 closeout

## Universal rules

Read BOOT.md, AGENTS.md, relevant architecture/roadmap, current code/tests and this plan. Check exact Git HEAD, clean/accepted dirty tree and expected version. Do not commit manually; runner owns implementation checkpoint commits. Increment **only root** package.json and root package-lock.json top-level/root version to each prompt's assigned 0.2.N; leave workspaces alone unless documented actual compatibility forces otherwise. Keep deterministic focused tests per implementation prompt, `git diff --check`; reserve one complete `npm run check` and browser, live account, restore evidence for final closeout. No claims of remote/device validation from synthetic fixtures.

P1 defines creator/catalog/media/manifest shapes: reuse validators. Preserve historical ChannelSpec v1 shape, IDs (`ch_*`), generator and offline P0 tests. Build tenant identity as a server-side verified principal, not a new client-controlled field in ChannelSpec. Do not introduce a shared multi-creator TV app.

All hosted flows must route via an authorization-enforcing, transaction-aware repository/service API. Use explicit LOCAL_LEGACY vs HOSTED modes (or equivalent) whose config validation rejects unsafe public listeners. Hosting fails closed on missing database/OIDC/storage requirements. Local P0 behavior may remain accessible only with explicit loopback-only setting, never by falling back in hosted mode.

## P1 — OIDC auth/session foundation (0.2.1)

Source targets: `apps/server/src/auth/*`, session/http middleware, `apps/server/src/api.ts` and config/test primitives; narrow Studio sign-in/session awareness as needed. Define a stable `AuthenticatedPrincipal` with internal account key and verified provider subject; an OIDC implementation with Google live issuer configuration and separate test fixture. Authorization Code + PKCE S256, state and nonce; verify ID token signature, issuer, audience, expiry, email verification when relied upon, and callback/redirect origin restrictions. Sessions: opaque server-side revocable, secure httpOnly SameSite cookies on HTTPS, login rotation, logout, expiration, CSRF on modifying requests. No generic `x-user-id` spoof header, unsigned JWT acceptance or demo auto-login in production. No need for Postgres-backed account storage before P2, but make session-store lifetime explicit and fail-closed; ensure P2 wires persistent account mapping. Focus tests on forged tokens, replay/state, expiry, wrong issuer/audience, CSRF, cookie and test-mode fences. Hosted project routes must reject unauthenticated access from this checkpoint onward, without breaking explicitly local P0 unit tests.

## P2 — Postgres ownership and persistence (0.2.2)

Targets: versioned `apps/server/migrations/*`, DB adapter/repository, server boot/config, contracts-mapping tests. Tables for provider subject/account, ChannelProject/spec+revision, ChannelOwnership, distinct ChannelDeployment/package, owner-scoped media/evidence metadata and migration/audit marker placeholders. Use bound SQL, tenant scoping, real transaction + revision CAS, DB constraints for ownership/FKs and globally unique package IDs. Project create/read/list/update and authentication account mapping persist across restart; never let request JSON select owner. Preserve `ch_*` ChannelSpec references; do not modify TV/runtime. Test two independent DB connections, concurrent CAS, wrong owner, duplicate package, malformed channel, migrations and rollback. Use an actual ephemeral or isolated Postgres DB in integration qualification; don't call an in-memory substitute SQL proof.

## P3 — Whole-surface API authorization and Studio integration (0.2.3)

Targets: `apps/server/src/api.ts`, `workspace.ts` service calls, `apps/studio/src/*` API/session/project switching and route tests. Require principal for every project-associated route: project list/create/read/update, mutations, agent/status, code overview/file read/save/generate, build/status, readiness, bundle and any exports. Authorize **before** reading project files/generating/downloading or invoking provider; share one scoped repository API that requires principal. Hide cross-owner existence and do not disclose storage roots or raw exception paths in HTTP output. Cross-account project mutation through body `spec.id`, URL, agent, file path and stale session must fail. In hosted mode disable CLI build and other unsafe shared execution unless independently sandboxed; return explicit not-available status. Preserve local historical behavior with non-public config guard. Studio shows login/logout, session-expired recovery and only the owner's projects, while Preview/editor semantics stay stable. Add table-driven route denial tests with two verified sessions, CSRF and owner/foreign IDs.

## P4 — Private object and secret boundaries (0.2.4)

Targets: storage interface/adapter, metadata tables, private object authorization service, tests/config. Support a private S3-compatible backend (and explicit isolated development/test equivalent) with opaque object names, creator-scoped metadata, short-lived authenticated download/upload capability where needed, no list-bucket permissions and no public bucket default. Provide limited evidence/media object primitives; full creator catalog uploads, license checking and transcoding belong to P3. Encrypted-at-rest/secrets references are server-only. Ban credentials, session cookies, signed URLs intended for private access, internal object paths from `ChannelSpec`, publishedManifest, generated code, log or export payloads. Test guessed object refs, foreign owner, expiry, revocation/deletion, oversized/unapproved types and failure cleanup.

## P5 — Explicit local P0 importer and portable source (0.2.5)

Targets: `apps/server/src/migration/*`, bounded CLI/admin import path and tests/runbook. An authenticated selected creator is the destination; no inferred ownership from P0 JSON or directory name. Dry-run default; explicit apply and audit. Read P0 `.firelaunch-data/projects/ch_*` read-only, reject symlinks/unsafe paths/invalid records, migrate legacy ChannelSpec through existing `migrateChannel` and preserve same IDs where safe. Keep revision, authored generated-source edits/generation baseline and meaningful code-artifact pointers as bounded private objects if supportable; otherwise hard-stop/manual recovery, **never silently delete custom code**. Transactional mapping, fingerprint/idempotency and collision reporting; originals not mutated. Verify source export independently of FireLaunch, accurate rights provenance (no inferred licenses), intentional rollback on partial failure. Automated fixtures cover corrupt project, symlink, ID collision, repeated imports and customization survival.

## P6 — Backup/restore and operational hardening (0.2.6)

Targets: explicit backup/restore tooling/runbook, health/audit/recovery APIs and tests. Back up DB and private object data with linked consistency manifest/checksums, no raw credentials, encrypted access and documented retention; restore into disposable namespace with integrity checks. Test crash after SQL transaction, object failure/orphan cleanup, multi-account restart, backup/recovery and import failure; ensure no public endpoint can launch restore/admin functions. Implement bounded account export/delete mechanics (actual data ownership/removal with audit and object revocation) without broad P7 billing/self-service UX. Add structured privacy-safe audit and operational health for failed auth/storage/import/restores. Avoid premature hosted deployment scripts that expose unauthenticated listener.

## P7 — Independent hosted qualification closeout (0.2.7)

Single final closeout; browser required. Inspect all runner checkpoints and exact candidate SHA. Independently exercise OIDC login via real configured issuer with two distinct legitimate creator identities on the actual hosted/test target, secure cookies/CSRF/logout/session expiry, hostile cross-tenant ID/API/file/agent/build calls, media/evidence capabilities, project list/create/edit, shared source export, restart, transactional conflicts/unique packages, legacy P0 migration and unchanged local originals, Postgres+object backup/restore on disposable resources, hosted disabled build, and non-regression of ChannelSpec v1/Vega/source. Run `npm run codex:stack:validate -- p2`, ONE `npm run check` with supported Node/npm, `git diff --check` and focused security negatives. Record exact URLs/test identities only in redacted form, toolchain versions, test counts, Postgres/storage engine, browser steps, failures, runtime artifacts, SHAs and GREEN/NOT GREEN in `docs/tasks/p2/closeout.md`. Advance root version to 0.2.7. If a real OIDC account/browser or SQL+object recovery gate cannot be exercised, mark NOT GREEN with a c2-* correction plan; don't replace it with mocks.

## P3 handoff

P3 can rely on verified CreatorAccount sessions, tenant-scoped relational/project access and private media/evidence foundations. It owns file/feed ingestion, source identity/provenance and rights curation, not a universal Amazon connector. P4+ retain non-mock AI, immutable TV manifests, permitted sync, creator Console submission and physical Appstore evidence.
