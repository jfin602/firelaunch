# c5-vega P3 — creator-owned HTTPS and one-package device handoff

This is a procedure, not live publication or device evidence. Start from the P2 runner checkpoint at root `0.6.0`; keep [original P5 NOT GREEN](../p5/closeout.md) unchanged. The P1 package at `.codex-runs/c5-vega/p1/bound-final/` is a **build fixture** pinned to `channels.example.org` and `com.example.firelaunchbuild`. Its recorded 541,474-byte VPKG/SHA-256 `e67b696ef8808c841e1d2f4918cf953c85479d450f62155b73d1708124653662` proves a build only. Never install it as proof of an approved creator release.

## Prerequisites and operator boundary

1. Record starting HEAD, Node/npm, `vega --version`, `vega sdk list-installed`, `vega device list/info`, target OS/architecture, and the actual P1/P2 source. On P2 inspection: Vega CLI 1.4.4 and SDK `main@0.24.12112` are installed; `vega device list` found no device. Start the VirtualDevice with GUI/GL as in [P5's runbook](../p5/P8-device-runbook.md) and verify its display. Record Ngest's existing owner-approved health check, URL/status and process/service state **before and after**; do not restart or reconfigure it.
2. Obtain creator authorization for a dedicated TV hostname, trusted certificate, DNS and an isolated fault-injection test origin. The operator performs/reviews any DNS, Nginx, firewall or password-SSH change. Keep `firelaunch.jfin.dev` as authenticated private Studio. Bind the hosted server to loopback; apply the exact GET-only allowlist in [public HTTPS staging](../p5/public-https-staging.md) on a separate TV vhost. Its only anonymous paths are `/public/v1/deployments/dep_<32 hex>/current` and `/public/v1/deployments/dep_<32 hex>/releases/rel_<32 hex>`. Reject all other paths and methods at the edge, including `/api`, Studio, upload/object routes, MinIO and DB; strip Cookie, Authorization and CSRF headers. Check externally that no backend port is reachable. Never expose local-legacy mode.
3. Use a real hosted database whose `firelaunch_schema_migrations` contains **10** and whose deployment/project ownership is backed by the verified OIDC session. Read its migration and release counts through the approved private admin path; do not seed publication tables or copy a fixture into a live database. The P2 local source database had migrations **1–9** and no publication tables. A disposable test database migrated through 10 for automated tests; that does not establish staging readiness.
4. Record permission evidence privately for an original or separately licensed **stable public HTTPS artwork** with `television_display` rights. For video/audio also require a separate asset and `television_playback` rights. A writing item may be informational and have no playback URL, but still needs cleared artwork. Review the catalog item and source permission, set eligible HTTPS asset bindings, and verify URLs from the device network. The checked-in placeholder, c0 demo, Amazon/Prime/YouTube content, private upload, signed URL and example-domain test media are not cleared fixtures. Keep evidence IDs, credentials and private object keys out of this report, generated source and public manifests.

## Create and approve the real deployment

5. In the authenticated Studio session, create or choose the creator's project and approved catalog draft. The new owner route is `POST /api/projects/:projectId/deployment`, once per project. It requires the normal session cookie, exact Studio `Origin`, `X-CSRF-Token` and JSON body `{ "appName": "<approved name>", "packageId": "<creator package ID>", "manifestEndpoint": "https://<separate-tv-host>/", "nativeReleaseApproval": "creator_approved" }`. The server derives account/project identity from the session/path, assigns the `dep_` ID, and stores `consoleEvidence: none`; no caller owner ID is accepted. Confirm the returned deployment by authenticated `GET /api/projects/:projectId/deployment`. This route records the creator's native identity approval; it does not publish or submit the app. Use the Studio's normal CSRF-bearing request flow or an owner-controlled same-origin client; do not paste session cookies or CSRF tokens into a report.
6. In Studio **Publish**, verify catalog selection, public HTTPS artwork binding and any playback binding. `POST .../publication/:depId/readiness` with current channel/catalog revisions, `expectedLiveReleaseId: null`, and bindings must succeed. The creator explicitly approves the v1 draft (`/approve`) then confirms `/publish` with its returned `approvalId`. Capture private status/history and public release ID, sequence **1**, SHA-256 and visibly identifiable v1 title. Approval alone is not live. Keep a distinguishable v2 **draft** ready; publish it only after the first installed-package v1 observation. A v3 rollback is an intention until current rights are rechecked and the owner separately approves/publishes it via `/rollback` then `/publish`.
7. Generate **fresh** source from that owned project spec and returned deployment, using `writeGeneratedProject(spec, emptyAbsoluteDirectory, deployment)` or the protected hosted source export. Verify `src/release-config.json` has the exact `deploymentId`, `channelId`, `packageId`, and dedicated HTTPS `origin`; `firelaunch.json` has no unresolved assets; inspect exported code for private/evidence/token fields. Hosted builds remain disabled, so build this ordinary exported/generated source locally with the compatible P1 SDK procedure. Record `vega project doctor`, actual Release build command/exit, nonempty VPKG path, byte count, SHA-256, app component/package ID and build log. No P1 example-origin package qualifies for this step.

## HTTP, same-VPKG and fault evidence

8. From host **and device network**, GET current and its matching immutable release over trusted HTTPS. Save exact response bytes privately; compare `sha256sum` of release bytes to current's `sha256` and quoted release ETag. Current uses `public, max-age=0, must-revalidate`; release uses `public, max-age=31536000, immutable`; matching `If-None-Match` returns 304. Current ETag hashes pointer JSON, so it differs from the manifest digest. Check foreign/unpublished IDs, query/extra segment, POST/HEAD, `/api`, Studio and object paths are 404/blocked **at the public vhost**. On private Studio, unauthenticated owner routes return 401, foreign project routes 404, and owner POST without valid CSRF/origin 403. Check manifest bytes contain no creator email/account, evidence, private object path, token, signed capability or executable code. Record actual TLS certificate/hostname validity and target-side reachability; host-only curl is insufficient.
9. Install the newly built exact VPKG **once** with `vega device install-app --device <serial> --packagePath <absolute-vpkg>`, then launch `<packageId>.main`. Record install count/time, target identity, SHA-256 and visible v1 focus/detail/Back plus device HTTPS fetch/release ID. Do not rebuild or reinstall for later steps. Publish the visibly changed, owner-approved v2 through private Studio; verify sequence **2**, pointer/digest and the **same installed package** visibly updates after refresh (up to the 60-second poll). Capture target logs/screenshots and remote request evidence.
10. Disconnect target network, cold-stop and relaunch; verify persisted last-known-good v2 with usable navigation. Restore network. Inject bad JSON/digest, wrong deployment/schema and bounded 404/5xx/timeout **only at the isolated test origin/controlled response layer** pinned in this test build. Never edit immutable database release bytes or a shared production pointer. For each fault, record rejection and usable v2, then restore the genuine endpoint and repeat a successful fetch. A simple host-side HTTP mock does not prove device fallback.
11. Creator selects historical v1 in Studio, rechecks **current** item/artwork/playback rights, approves rollback and separately confirms publication. The result must be a new release ID and sequence **3** with `previousReleaseId=v2` and `rollbackSourceReleaseId=v1`; v1/v2 exact bytes remain unchanged. Observe the same installed package return to v1 content without reinstall. Re-run public route negatives, owner/foreign/CSRF checks and Ngest pre/post health checks.

## Evidence ledger and stop conditions

Record redacted TV/Studio origins, rights decision, migration 10, creator project/deployment/package IDs, v1/v2/v3 approval/release IDs and hashes, pointer transitions, HTTP headers/negative statuses, exact VPKG hash and **one** install count, device OS/logs/screenshots, fault setup/restore, Ngest checks and any skip. Stop with `NOT GREEN` for missing rights, real creator session/deployment, separate HTTPS origin, installed VPKG, device network evidence or same-package sequence. P3 alone runs the final npm 12 aggregate and writes `docs/tasks/c5-vega/closeout.md`; do not relabel historical P5 or claim physical Fire TV/Appstore qualification.
