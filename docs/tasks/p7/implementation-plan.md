## P2 — Isolated build, lifecycle, ZIP and Studio download

Implementation seams: `apps/server/src/hosted-workspace.ts` and `api.ts`, a narrowly scoped isolated worker adapter, `apps/studio/src/api.ts` and `Delivery.tsx`, tests and operations/runbook. The build worker must actually be isolated from VPS server and provider credentials (separate host or hardened isolated VM/container with no host mounts, unprivileged identity, bounded network, CPU/memory/disk/process/time, per-job scratch and enforced cleanup). Interface should support explicit job creation/status/result, idempotent and replay-safe owner/revision/deployment fingerprint, one/tightly bounded creator concurrency, timeout/cancel/expiry, sanitized error reasons. Startup without verified worker capability must remain disabled/blocked.

Secure API: existing signed-in `/api/projects` ownership and CSRF for mutation, no insecure arbitrary file or command parameters; job and artifact identifiers opaque, expiry/size bounds, revalidate owner/project + input fingerprint before download, foreign/no-session/expired/revoked/changed-source denial and no cross-tenant build artifacts. Use a durable bounded lifecycle so API restart does not fabricate success; on stale work show explicit blocked/expired state. ZIP is constructed only after verified fresh real x86_64 VPKG, with `README.md`, `export-info.json`, `SHA256SUMS`; verify archive entries/relative names and hashes. Browser download uses authenticated streaming Blob/Content-Disposition with CSRF-guarded creation and correct errors; show Created/Queued/Building/Ready/Failed/Expired without fake progress. Do not confuse existing JSON `code/export` or `bundle` with installable native ZIP. Worker or downloadable-artifact integration may require an authorized separate operator configuration; no VPS/cloud deployment is authorized here. If isolation cannot be assured, keep UI unavailable and report exact blocker rather than making a fake ZIP.
