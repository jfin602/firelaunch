# Cycle 3 — Media and final release candidate

- **Starting HEAD/version:** `87fb34c4822b7e866e6759060bbbd4acbc658e7a` / `0.0.7`; prior working-tree repairs present.
- **Failed gates:** G3 reachable media/artwork and G5 decoded playback.
- **Observe:** The virtual device's `curl` returned HTTP 200 for a host-served FireLaunch demo clip, but the app never requested that plain HTTP URL; the video screen showed no frames. Amazon's [media setup guide](https://developer.amazon.com/docs/vega/0.24/media-player-setup) lists missing media service permissions. With reachable HTTPS CC0 media, the simple `Video` component advanced its timer but did not display frames in this test. The [documented `VideoPlayer` surface path](https://developer.amazon.com/docs/vega/0.24/media-player-select-playback) displayed decoded frames and device `timeupdate` events.
- **Diagnose:** The manifest lacked media capabilities, the sample's loopback URL was inaccessible from an independent TV, and the `Video` component was insufficient for visible playback on this target. The observed plain HTTP media failure was not generalized to all HTTP support.
- **Repair:** Added the documented media service requests to `templates/vega-channel/manifest.toml` and changed the template playback to `VideoPlayer` with `KeplerVideoSurfaceView`, initialization, mute/autoplay configuration, and teardown. For the qualification candidate, used HTTPS media and HTTPS artwork from MDN's `cc0` media collection. The default Studio demo's local SVG and loopback references remain unresolved and are listed in the closeout.
