# P8 independent installed-VPKG / HTTPS qualification runbook

This is a procedure, **not evidence of P5 GREEN**. P7 validated deterministic local Postgres/HTTP/native-client paths, not a public HTTPS origin or installed device. Use the same deployment and package throughout; record the P7 runner checkpoint, candidate source tree and exact toolchain before starting. Do not reuse the historical c0 VPKG as proof of this release client.

## Preflight and bounded origin

1. Verify `node --version` is 24.x, use npm 12 (`npx --yes npm@12.2.0` if PATH npm is 11), run `vega --version`, `vega sdk list-installed`, `vega device list`, `vega device info --device <serial>`. On the 2026-10-11 P7 host the CLI reported **1.4.4**, active SDK **main@0.24.12112** at `/home/jfin/vega/sdk/vega-sdk/main/0.24.12112`; `vega device list` reported **no devices**. The c0 test target was `VirtualDevice` x86_64 TV OS 1.2. Start with `vega virtual-device start --gui --gl-accel --timeoutSeconds 90` and inspect its screen. In c0, headless/no-acceleration appeared ready but displayed black. Linux Mint 22.3 is not explicitly listed as a supported host; do not generalize a successful build to host qualification.
2. Provision a **controlled, device-reachable HTTPS hostname** with a trusted certificate and stable pinned origin. Follow [public-https-staging.md](public-https-staging.md): only allow `GET /public/v1/deployments/<deployment>/current` and `GET /public/v1/deployments/<deployment>/releases/<release>`. Private hosted server on loopback, with owner `/api`, Studio, database and object store blocked from that vhost. Never expose local-legacy or tunnel the whole server. Verify certificate and anonymous read **from the VirtualDevice network**, not only the host. Record redacted origin, TLS and route-denial evidence. Stop if the origin cannot be reached safely.
3. Use a verified creator session and a creator-owned deployment. Choose a creator-owned rights-cleared video/audio **and** display artwork with stable public HTTPS URLs, separately approved playback/display rights and recorded evidence; or use informational writing with independently rights-cleared artwork, no fake playback binding. `assets/catalog-placeholder.png` and the c0 loopback demo are **not** cleared publication fixtures. The current schema requires artwork even for informational books: do not invent a text-only exception. Use non-sensitive, distinguishable v1/v2 titles, and keep credential/evidence/private object IDs out of logs and manifests.

## One binary, several releases

4. Approve and publish v1 with the owner-only publication API/Studio. Capture project/deployment/package IDs, approved channel/catalog revisions, release ID/sequence, canonical release SHA-256 and current pointer. Fetch current and immutable release anonymously; check the digest of the **exact response bytes**, strict cache headers (`max-age=0, must-revalidate` for pointer; `max-age=31536000, immutable` for release), `ETag`/304, foreign deployment/release 404 and blocked `/api`/Studio. Confirm neither bytes nor exported source contain secrets, signed URLs, private paths or evidence; inspect TV media URLs and ownership/rights again.
5. Generate **once** from that deployment with its pinned HTTPS `manifestEndpoint`. Verify generated `src/release-config.json`, deployment/package identity, native compatibility, `firelaunch.json` unresolved assets and `vega project doctor` in generated directory. Install declared dependencies, run `./node_modules/.bin/react-native build-vega --target x86_64 --build-type Release`, require an existing nonempty `.vpkg` and record `sha256sum <artifact.vpkg>`, size and build output. Never treat `vega build` success without bundled JS as sufficient (c0 discovered this failure). Run `vega device install-app --device <serial> --packagePath <artifact.vpkg>` **once**; record install time and package identity. Launch with `vega device launch-app --device <serial> --appName <package.id>.main`. Capture actual visible Home/focus/detail/Back and the accepted v1 ID/sequence/digest on-device.
6. Edit the *draft*, review rights/revisions, explicitly approve and publish v2 (visible title/content change); observe pointer and release hashes at origin and the **same installed app** accepting v2 without another build/install. Record target-side HTTPS requests/logs and screenshots, release ID/sequence/digest and D-pad detail/Back. If app refresh is periodic, wait beyond its 60-second interval and distinguish cached v1 from fetched v2.
7. Disconnect the device network, cold-stop and relaunch that package; verify persisted LKG v2 and navigation. Restore network; serve an intentionally bad digest, wrong deployment or incompatible schema behind the **isolated test origin** (never modify immutable stored production release bytes). Verify refusal while v2 remains usable, then restore the genuine endpoint. Also test timeout/404/5xx or offline fallback. Record how the fault was injected and removed; do not mistake a host-only simulation for device proof.
8. Owner explicitly reviews the historical v1 selection against *current* rights and publishes rollback as a **new** v3; check v3 sequence > v2, `previousReleaseId=v2`, new ID/hash, unmodified v1/v2 bytes and the same installed package visibly returning to v1 content after refresh. Revoked rights must block a new approval/publish; disconnected devices may retain old LKG indefinitely, so do not claim immediate offline revocation.

## Evidence and disposition

Record exact commands, redacted logs and screenshots, manifest bytes/digests, pointer transitions, VPKG SHA-256, installed-app identity, target OS/architecture, one installation count, HTTP/TLS responses, and any skipped or blocked step in `closeout.md`. Run focused regressions, one `npm run check` using Node 24/npm 12, `npm run codex:stack:validate -- p5`, and `git diff --check`. P5 is **NOT GREEN** without direct same-installed-VPKG VirtualDevice + device-reachable HTTPS update, offline/fault fallback and owner rollback evidence. VirtualDevice can qualify P5, not physical Fire TV or Appstore. Preserve original P4 live non-mock gate and hosted S1–S6 OPEN/PARTIAL; Phase 6 source sync, Phase 7 Console handoff and Phase 8 physical/Appstore remain separate.
